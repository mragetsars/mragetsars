# نگهداری پروفایل GitHub

این مخزن، README پروفایل `mragetsars` را نگهداری می‌کند. معرفی و مهارت‌ها متن معمولی Markdown هستند؛ چهار بخش نشانه‌گذاری‌شده با اطلاعات عمومی GitHub به‌روز می‌شوند.

## چه اطلاعاتی خودکار است؟

| بخش | منبع و رفتار |
| --- | --- |
| معرفی کوتاه | Bio، Company و Location حساب GitHub |
| راه ارتباطی | فیلد Website حساب؛ اگر نشانی تلگرام باشد، با عنوان Telegram نمایش داده می‌شود |
| پروژه‌های منتخب | انتخاب از `profile.json`؛ نام واقعی مخزن در لینک، خلاصهٔ توضیح About، زبان اصلی، ستاره و زمان آخرین push از API |
| آمار | تعداد مخازن عمومی، دنبال‌کنندگان و ستاره‌های دریافت‌شده |
| پروژه‌های دیگر | سه مخزن با جدیدترین زمان push؛ بدون تکرار منتخب‌ها، forkها، مخزن پروفایل و مخازن آرشیوشده |
| تاریخ تازگی | روز آخرین دریافت موفق، بر اساس UTC |

ستاره‌های دریافت‌شده از مخازن عمومی متعلق به این حساب محاسبه می‌شوند؛ forkها و مخزن خود پروفایل در این جمع نیستند. مخازن آرشیوشده در این آمار حساب می‌شوند. عدد «مخازن عمومی» همهٔ مخازن عمومی این حساب، از جمله forkها و مخزن پروفایل، را شامل می‌شود.

«Last push» زمان `pushed_at` گیت‌هاب است؛ به‌معنی آخرین release، تکمیل پروژه یا فعالیت صرفاً انسانی نیست. زبان اصلی هم تشخیص GitHub از مخزن است، نه درجهٔ مهارت. برای مثال `Jupyter Notebook` به قالب اصلی آن مخزن اشاره دارد.

نام کامل، متن معرفی، جدول مهارت‌ها، انتخاب پروژه‌ها و ترجمهٔ فارسی عمداً دستی هستند. تغییر تحصیلات، شغل یا سطح مهارت از تعداد commitها حدس زده نمی‌شود. اگر وضعیت تحصیل یا محل کار تغییر کرد، Bio و Company حساب را اصلاح کن؛ متن آزاد README را نیز در صورت نیاز ویرایش کن.

## اجرا و فعال‌سازی

فایل workflow در `.github/workflows/update-profile.yml` قرار دارد و باید روی شاخهٔ پیش‌فرض `main` باشد. برنامهٔ زمان‌بندی آن هر روز ساعت **04:17 UTC** است؛ با اختلاف فعلی ساعت تهران، **07:47 تهران**.

برای اجرای دستی، در مخزن به **Actions → Update profile → Run workflow** برو و شاخهٔ `main` را انتخاب کن. نصب کتابخانهٔ Python یا ساخت توکن شخصی لازم نیست؛ workflow از `GITHUB_TOKEN` موقت GitHub استفاده می‌کند.

اگر Actions برای مخزن خاموش باشد، باید فعال شود. سطح دسترسی نوشتن تنها برای job به‌روزرسانی تعریف شده است. محدودیت سازمان یا قوانین محافظت از `main` ممکن است push خودکار را مسدود کنند؛ workflow چنین محدودیتی را دور نمی‌زند. در این حالت از روند مجاز pull request مخزن استفاده کن یا مجوز مشخص لازم را با سیاست خودت هماهنگ کن.

زمان‌بندی GitHub تضمینِ اجرای دقیق در همان دقیقه نیست و ممکن است تأخیر داشته باشد. GitHub همچنین می‌تواند زمان‌بندی مخزن عمومی بدون فعالیت را پس از ۶۰ روز غیرفعال کند. برای وضعیت واقعی، لینک **Refresh status** در پایین README را بررسی کن.

## ویرایش متن و پروژه‌ها

متن بیرون از این چهار جفت نشانه را آزادانه ویرایش کن:

```text
<!-- PROFILE:START --> … <!-- PROFILE:END -->
<!-- PROJECTS:START --> … <!-- PROJECTS:END -->
<!-- ACTIVITY:START --> … <!-- ACTIVITY:END -->
<!-- UPDATED:START --> … <!-- UPDATED:END -->
```

متن داخل این بخش‌ها در اجرای بعدی بازتولید می‌شود. نشانه‌ها باید یکتا و بدون تداخل باقی بمانند.

برای تغییر منتخب‌ها، فهرست `featured` در `profile.json` را ویرایش کن. هر مورد دو فیلد دارد: `id` شناسهٔ عددی واقعی مخزن و `label` عنوان کوتاه نمایشی. شناسه را از API همان مخزن بگیر؛ شناسهٔ عددی در تغییر نام ثابت می‌ماند. حداکثر هشت پروژه پشتیبانی می‌شود و ترتیب نمایش، همان ترتیب فایل است.

پروژهٔ حذف‌شده، خصوصی‌شده یا منتقل‌شده به حساب دیگر از انتخاب‌ها کنار می‌رود. پروژهٔ آرشیوشدهٔ منتخب با برچسب Archived دیده می‌شود. توضیح پروژه از اولین جملهٔ About گرفته می‌شود و برای خوانایی ممکن است کوتاه شود؛ برای تغییر آن، About همان مخزن را اصلاح کن. عنوان کوتاه `label` همچنان انتخاب خودت است.

پس از تغییر `profile.json` یا کد تولید، خروجی را بازتولید و فایل‌های تغییرکرده را با هم commit کن:

```bash
python3 scripts/update_profile.py --offline
python3 -m unittest discover -s tests -v
python3 scripts/update_profile.py --offline --check
```

حالت offline از `data/profile.json` استفاده می‌کند و اینترنت نمی‌خواهد. برای دریافت تازه از GitHub:

```bash
python3 scripts/update_profile.py
```

اجرای محلی به Python 3.11 یا جدیدتر نیاز دارد. بدون توکن، دادهٔ عمومی قابل دریافت است اما محدودیت درخواستِ ناشناس GitHub اعمال می‌شود. در صورت نیاز، توکن را فقط از متغیر محیطی `GITHUB_TOKEN` بده و هرگز آن را در فایل‌ها ننویس.

## رفتار در خطا

- خطای API، دادهٔ نامعتبر یا اشکال در نشانه‌ها پیش از نوشتن خروجی تشخیص داده می‌شود؛ نسخهٔ ذخیره‌شده با دادهٔ ناقص جایگزین نمی‌شود.
- خطای موقت شبکه یا محدودیت درخواست حداکثر سه بار تلاش می‌شود؛ سپس workflow شکست را گزارش می‌کند.
- README فقط در چهار بخش مشخص تغییر می‌کند. فایل‌های دیگر در commit روزانه وارد نمی‌شوند.
- اگر هم‌زمان `main` تغییر کند، push معمولی رد می‌شود؛ force push وجود ندارد. پس از بررسی، اجرای تازه را شروع کن.
- درخواست‌های pull request فقط آزمون و بررسی خروجی را اجرا می‌کنند و مجوز نوشتن ندارند.
- تاریخ تازگی روزانه تغییر می‌کند تا موفقیت دریافت داده قابل مشاهده باشد؛ اجرای تکراری با داده و تاریخ یکسان commit اضافی نمی‌سازد.

هر فایل جداگانه به روش atomic جایگزین می‌شود؛ عملیات نوشتن چند فایل، تراکنش مشترک فایل‌سیستم نیست. در GitHub فقط پس از موفقیت تولید و بررسی خروجی، هر دو فایل با یک commit منتشر می‌شوند.

## ظاهر

دو فایل SVG داخل `assets` مخصوص حالت روشن و تیره هستند. بنر ثابت است، فونت یا سرویس آمار خارجی بارگیری نمی‌کند و محتوای ضروری به اجرای انیمیشن وابسته نیست. اطلاعات اصلی و لینک‌ها در متن README نیز وجود دارند. نام تاریخی فایل‌های `profile-neofetch-*` برای حفظ مسیرهای موجود نگه داشته شده است.
